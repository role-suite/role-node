# Telemetry Conventions

## Goals

- Keep telemetry consistent across logs, metrics, and traces.
- Preserve request-level correlation from edge to storage.
- Avoid sensitive data leakage in telemetry payloads.

## Resource Attributes

- `service.name`: `OTEL_SERVICE_NAME`.
- `service.version`: `OTEL_SERVICE_VERSION`.
- `deployment.environment.name`: `NODE_ENV`.

## Correlation

- Continue using `x-request-id` for request-scoped correlation in logs.
- Include `traceId` and `spanId` in all structured production logs.
- Include `traceId` and `spanId` in development log prefixes for local debugging.

## Span Naming

- HTTP server spans: generated by OTel instrumentation.
- gRPC client/server spans: generated by OTel instrumentation.
- Custom spans (future batches): `<module>.<operation>` (for example `workspaces.create`).

## Metric Naming

- Prefer OTel semantic conventions where available.
- Custom metric format: `role.<domain>.<signal>`.
- Use base units (`ms`, `bytes`, count as unitless integer).

## Redaction Policy

- Never log or export plaintext secrets, tokens, or passwords.
- Do not include full request/response bodies unless explicitly redacted.
- Hash or mask stable identifiers when full values are unnecessary.

## Baseline SLO Targets

- Availability: 99.9% monthly for REST and gRPC entry points.
- Latency: p95 under 300 ms for standard read operations.
- Error rate: below 1% for non-4xx server failures.

## Environment Variables

- `OTEL_ENABLED`: enables/disables telemetry bootstrap.
- `OTEL_SERVICE_NAME`: logical service identity.
- `OTEL_SERVICE_VERSION`: release version tag.
- `OTEL_EXPORTER_OTLP_ENDPOINT`: OTLP HTTP endpoint base URL.
- `OTEL_METRICS_EXPORT_INTERVAL_MS`: metrics push interval.
